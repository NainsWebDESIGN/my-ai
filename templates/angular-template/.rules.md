## 命名慣例

| 類型 | 規則 | 範例 |
|------|------|------|
| Component | `kebab-case` 檔名，`PascalCase` Class | `user-list.component.ts` → `UserListComponent` |
| Service | `kebab-case` 檔名，`PascalCase` Class | `api.service.ts` → `ApiService` |
| Module | `kebab-case` 檔名，`PascalCase` Class | `user.module.ts` → `UserModule` |
| Interface / DTO | `PascalCase` | `UserDto`, `LoginRequest` |
| Route path | `kebab-case` | `/user-list`, `/member-banned` |
| Selector | `app-` prefix + kebab-case | `app-user-list` |

## 檔案結構

每個 Component 必須包含三檔（除非模板/樣式極簡可內嵌）：
```
feature-name/
├── feature-name.component.ts
├── feature-name.component.html
└── feature-name.component.scss
```

## 表單規範

- 優先使用 **Reactive Forms**（`FormBuilder` + `Validators`）
- 表單送出前執行 `markAllAsTouched()` 觸發驗證顯示
- 每個 FormControl 必須有明確型別

## HTTP 錯誤處理

- Service 層：使用 `catchError` 統一處理，回傳 `throwError`
- Component 層：依 `HttpErrorResponse.status` 決定 Toast 類型與訊息
- 載入中：用 `BehaviorSubject<boolean>` 或 component `isLoading` 變數控制

## E2E 規範

- 每個互動元素加 `[attr.data-testid]="'xxx'"` 屬性
- Toast / Dialog 使用固定文案，不依賴動態文字做 selector

## Commit 規範

- 格式：`feat(scope): 簡短描述`
- 類型：feat / fix / refactor / style / docs / test / chore
